A region is a Fly.io datacenter. [Machines](machines.md), [Volumes](../data/volumes.md), [Postgres](../data/postgres.md) clusters, and a [Redis](../data/redis.md) primary live in one. An [App](apps.md) is global. It is not pinned to a region.

Alchemy defaults to `iad` (Ashburn, Virginia). Pass `region` to put a [Service](services.md), Machine, or Postgres cluster somewhere else.

## Pin a Service

```typescript
export default class Api extends Fly.Service<Api>()(
  "Api",
  { main: import.meta.url, region: "lhr", port: 3000 },
  Effect.gen(function* () {
    return {
      fetch: Effect.succeed(HttpServerResponse.text("hello")),
    };
  }),
) {}
```

`count` Machines run in that region.

## Pin a Machine

```typescript
const web = yield* Fly.Machine("Web", {
  app: Site,
  region: "syd",
  image: "nginx:alpine",
});
```

Each Machine resource is one VM in one region. To run in two regions, declare two Machines.

## Volumes stay in the region

A Volume is created in the parent Service or Machine’s region. It cannot move and cannot attach to a Machine in another region.

Restore into a new region from a [`VolumeSnapshot`](https://alchemy.run/providers/fly/reference/volume#volumesnapshot) with `snapshotId` on the mount.

## Several regions, one hostname

Pass a list to `region` to run the same Service in several regions behind one hostname. `count` Machines run in each region, and Fly’s Anycast proxy sends each request to the nearest healthy Machine.

```typescript
export default class Api extends Fly.Service<Api>()(
  "Api",
  { main: import.meta.url, region: ["iad", "lhr"], count: 2 },
  Effect.gen(function* () {
    return {
      fetch: Effect.succeed(HttpServerResponse.text("hello")),
    };
  }),
) {}
```

One hostname, Machines in two regions. Fly's Anycast proxy sends each visitor to the nearest healthy Machine.

This runs four Machines: two in `iad` and two in `lhr`. `api.regions` is `["iad", "lhr"]`, and `api.url` serves from both.

Adding or removing a region updates the Service in place. Its App and hostname stay the same, Machines in regions you keep are left alone, and a removed region’s Machines are deleted. A Volume from `MountVolume` is created in each Machine’s own region.

## Which region is this?

Fly sets `FLY_REGION` on the Machine. Read it in a Service with `Config`.

```typescript
import * as Config from "effect/Config";

const region = yield* Config.String("FLY_REGION");
```

## Postgres is regional

The cluster lives in one region. Pass `region` on [`Fly.Postgres`](../data/postgres.md), not on the App.

```typescript
const db = yield* Fly.Postgres("Db", {
  region: "iad",
});
```

## Redis primary

[`Fly.Redis`](../data/redis.md) takes `primaryRegion`. Default is `iad`. Read replicas are extra regions on `readRegions`.

```typescript
const cache = yield* Fly.Redis("Cache", {
  primaryRegion: "iad",
  readRegions: ["sjc"],
});
```
